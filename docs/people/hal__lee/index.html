TA 到底在做什么？

Hal 的工具都在解决同一类问题：设计稿到代码之间的损耗。Heron Handoff 把 Figma 设计导出为可离线浏览的标注文档；Figma Icon Automation 借助 GitHub Actions，把图标设计稿直接转成 React 组件并发布到 NPM；Figmacode 则从思维层面教设计师用组件化、自动布局和变量去「工程化设计」。

近两年 TA 把注意力转向 Mac：策展网站 MacMenuBar.app、在菜单栏显示 Figma 活跃度的 FigmaActivityCalendar，以及 2026 年上架的休息提醒 SkyBreak。

观点与方法

Hal 认为设计师缺的不是审美，而是工程化和系统化的思维：设计稿应该更接近开发实现，交付才会更容易。所以 TA 的课程里有「动态地设计」「响应式设计」「组件式设计」，也有「用代码来操作 Figma」「实现一个简单的插件」。

像一个工程师那样思考设计，让我们的设计稿更接近开发实现，交付更容易。

— Figmacode「工程化设计」章节

可以从 TA 身上学什么

  • 为自己的职业造工具：设计师最懂设计师的痛。
  • 插件是很好的起点：Figma 插件分发成本低、反馈快。
  • 把经验写成课程：系统化的知识比零散的技巧更有价值。
  • 策展也是产品：认真分类的清单能长期获得流量。
  • 给自己的爱好留时间：徒步和摇滚乐也是灵感来源。
