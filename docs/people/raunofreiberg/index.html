做 Devouring Details 之前，Rauno 问自己：「我是怎么学会的？」答案是：先做出一个想法，发现它在实践中很糟糕；迭代足够多次，有时甚至是意外，就会到达一个感觉很好的地方，然后突然能说清它之前为什么糟糕。这本手册想做的，就是把这些顿悟时刻变成捷径。

他到底在做什么？

Rauno 用代码做设计。他的原型常常只关注一个瞬间：输入框消失、工具栏变形、文字模糊显现、滚轮选择器、X 光透视，但正是这些瞬间决定了产品的质感。他把这些原型按时间放在 rauno.me/craft，每一个都有「View Prototype」或「View Production」。

2025 年起，他把经验体系化：Devouring Details 是一本面向「对交互好奇的设计师」的参考手册；History of Software Design 则试图「修复」软件史上影响深远的设计瞬间，从 Xerox Alto 的 Smalltalk-76 到 iPhone 的滑动解锁。

代表作品详解

Devouring Details ↗

2025交互参考手册付费

「An interactive reference manual for interaction-curious designers.」23 章，每章附一个可下载的 React 组件，所有演示都是真实组件录制。分为三部分：Principles（推断意图、交互隐喻、人体工学、模拟物理、动效编排、响应式界面、受限手势、汲取灵感）、Prototypes（单个组件的深挖，如 Line Minimap、Radial Timeline、Morph）和 Resources。

他强调这不是线性课程：没有代码挑战、测验或分步教程，而是一本可以反复翻阅、复制代码的手册。

History of Software Design ↗

2026交互展览进行中

「How did we get here? No one really knows.」软件史的书籍、纪录片和交互展览都很少，经典作品每年都在消失。这个项目选取几个影响巨大的设计瞬间进行「修复」：从模糊的历史素材里逆向还原细节、动效和行为。示例是 Freddy Anzures 2007 年的 iPhone 滑动解锁。

2023清单★1.9 千

设计观点

Have you ever noticed that some animation sequences can be improved with just a touch of delay? Or that some interactions just feel better without any motion at all?

— Rauno Freiberg，Devouring Details

他的观点散落在原型、清单和长文里：好的交互要能推断用户意图；动效要编排而不是堆砌；有时最好的动效是没有动效。他说自己也把 Devouring Details 当参考手册，在设计时定期回来复制代码、巩固理解。

维度长处局限 / 需要留意

可以从他身上学什么

  • 细节是可以学的：把「感觉对了」拆成具体的原则和组件。
  • 用原型思考：在真实交互里迭代，而不是在静态稿里争论。
  • 为每一年留档：年度原型站是最好的作品集。
  • 写清单：把经验写成别人能直接对照的规则。
  • 学习历史：理解软件设计的过去，才能设计未来。
