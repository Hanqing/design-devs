Matt Perry：为了写一本书，写了 12 年动画库

他住在阿姆斯特丹。2014 年，他觉得只用 CSS 做出的界面「很 webby，有点卡顿」，于是写了第一个动画库 Popmotion。后来他加入 Framer，做出了 Framer Motion：API 极简，却保留了 Popmotion 的无限可能，成为 React 世界最流行的动画库。2024 年，Motion 脱离 Framer 独立，改名 Motion，同时支持 React、Vue 和原生 JavaScript，GitHub 上有 3.4 万颗星，GTA VI 的官网也用它。现在他靠付费的 Motion+ 和企业赞助全职维护它，2026 年又推出了可视化编辑工具 Motion Studio、组件库 Motion UI，并开始写那本拖了 12 年的书：The Book of Motion。

2026 年 8 月，Matt 发帖说：很久以前，他坐下来准备写一本关于动画的书，结果写了 12 年动画库。「终于，这本书来了。」The Book of Motion 的引言叫《The Scenic Route》。他还说，越研究越坚定一个观点：认为动画只应该用来传递信息或教学，是非常错误的。情绪反应比逻辑思考更快，动画的价值恰恰在于它能直接触动情绪。

他到底在做什么？

Motion 的目标是把浏览器原生动画的性能，包装成好用的 API。早年 CSS 和浏览器 API 能力有限，Popmotion 自己算每一帧；如今有了 Web Animations API 和 Intersection Observer，Motion 尽可能交给浏览器硬件加速，同时保留 Framer Motion 的「超能力」：布局动画、共享元素过渡、手势、滚动联动、3D。

他在 Motion Magazine 上写技术长文：《The Web Animation Performance Tier List》给各种动画属性的性能排了座次；《A View Transition API for the rest of us》介绍 Motion 对视图过渡的封装；还有如何给 GSAP 的缓动函数做硬件加速。开发 UI Gallery 时，他要让所有 2D、3D 排列之间都能顺滑切换，还要避免图片的运动路径交叉。

本页依据 motion.dev（首页、About、Magazine）、GitHub 和 X 帖子整理，资料截至 2026 年 10 月。他加入和离开 Framer 的具体年份未在 About 页写明，独立时间依据《Motion's independence: One year in review》（2025 年 11 月）推算。

可以从他身上学什么

  • 不满意就自己写：Popmotion 就是这样开始的。
  • API 越小越好：几行代码就能出效果。
  • 跟着平台演进：浏览器能做的交给浏览器。
  • 开源也能独立生存：开源核心 + 付费增值。
  • 动画不只是信息：它也传递情绪。
