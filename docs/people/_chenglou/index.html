一句话：一个总在做「底层原语」的工程师，但每个原语都从用户能感受到的问题出发：动画被打断时的突兀、聊天列表里文字高度算不准造成的跳动、布局代码里潜伏的 NaN。

他到底在做什么？

Cheng Lou 的作品可以排成一条线：react-motion 回答「动画怎样才能随时被打断」；Reason 回答「类型安全的函数式语言怎样进入前端」；Pretext 回答「不读 DOM 怎样知道一段文字有多高」；Freerange 回答「不打开浏览器怎样确定布局不会出错」。

2026 年的几个项目还有一条暗线：给 AI 一个可以自动对照的真值。Pretext 用浏览器字体引擎作为基准，Freerange 在编译期给出每个数字的取值范围，handwired 把普通程序写成精确、可微分的神经网络。他在探索的是：AI 写的底层代码，怎样才能被证明是对的。

本页依据 GitHub、项目 README、chenglou.me、Reason 官方博客与 Pretext 的公开报道整理，资料截至 2026 年 10 月。Pretext 的性能数字和传播数据来自二手报道，未经独立验证。

代表作品详解

Pretext ↗

2026.03TypeScriptDOM / Canvas / SVG

「Fast, accurate & comprehensive text measurement & layout.」浏览器里要知道一段文字排出来有多高，通常得先把它放进 DOM，再调用 getBoundingClientRect 或 offsetHeight。这会触发重排，是浏览器里最昂贵的操作之一。虚拟滚动、聊天列表、瀑布流都被它拖累。

Pretext 自己实现了测量和断行逻辑：prepare() 一次性把文本分段测量，layout() 之后只做纯算术，因此可以在 DOM 出现之前就算出排版结果，并渲染到 DOM、Canvas 或 SVG。它支持「你可能都不知道存在的语言」，并用浏览器自己的字体引擎作为对照基准。

  • 演示页（chenglou.me/pretext）有气泡聊天、杂志式分栏、文字绕图等效果，都是原生 CSS 做不到或做起来很慢的。
  • README 特别说明：演示是「推荐阅读的 API 用法范例」，不随 npm 包发布。
  • 据二手报道，gzip 后约 15KB，零依赖；发布 48 小时内收获超过 1.8 万星。

react-motion ↗

2015JavaScript弹簧动画

「A spring that solves your animation problems.」传统动画用「持续 300ms + ease-out」描述，一旦中途被打断就会跳变。react-motion 改用物理模型：你只声明目标值（spring(10)），弹簧负责从当前状态平滑过渡过去，随时可以换目标。

这一观念转变影响深远：今天几乎所有主流前端动画库都把「弹簧」作为默认选项。

Freerange ↗

2026.04TypeScript静态分析

「Statically verify your layout code.」它会告诉你 TypeScript 代码里每一个 number 的取值范围，从而找出潜在的 NaN、Infinity、除以零和数组越界。

设计原则很克制：使用官方 TypeScript API，不是新语言也不是分叉，不需要任何注解；在编译期运行，耗时只占 TypeScript 分析时间的一小部分；并且「由 Agent 对着几千个边界情况做过对抗测试」。README 里那句话点明了它的用意：AI Agent 从此可以不打开浏览器，就保证 UI 布局正确。

handwired ↗

2026.10TypeScript实验

「把普通 JavaScript 代码变成神经网络：无需训练、结果精确、并且完全可微。」程序由 if-else、循环和状态组成；handwired 把它们改写成矩阵乘法和 ReLU 的组合。比如 (a > 4) ? 10 : 12 可以写成两个 ReLU 的差再加权求和。整个程序最后汇成一个大矩阵乘法，可以在 JS 或 WebGPU 上运行。

个人网站研究

chenglou.me ↗

页面标题就是「My Midjourney AI Art」：没有简历、没有博客，只有一张张他用 Midjourney 生成的图，提示词作为图注，比如「Jupiter planet sitting on a chair on Saturn」「Miniature watermelon delicately balanced on fingertip」。

但这个网站真正的作品是交互本身。源码 README 写得很直白：这是一个「为了展示闪亮的 UI/UX 细节」而做的画廊，并逐条列出了十几项细节，每项都配了一段演示视频。

观点与方法

A spring that solves your animation problems.

— react-motion README

It implements its own text measurement logic, using the browsers' own font engine as ground truth (very AI-friendly iteration method).

— Pretext README
  • 换一个模型看问题。动画不一定要用「时长」描述，用「物理」描述就自然可中断；排版不一定要问 DOM，自己算也可以算准。
  • 警惕过早抽象。《On the Spectrum of Abstraction》的核心是：抽象是一条光谱，越抽象越强大，也越难懂、越难改，要根据问题选择站在哪里。
  • 给 AI 一个真值。可自动对照的基准，让 AI 辅助开发可以不断逼近正确答案。Pretext、Freerange 都是这样做出来的。
  • 演示即文档。Pretext 的演示页、chenglou.me 的视频清单，都让底层能力变得人人能看懂。

长处与局限

维度长处局限 / 需要留意
影响力react-motion 和 Pretext 都改变了前端社区思考某类问题的方式很少写长文，观点主要散落在 README、推文和演讲里
工程从动画、语言到排版、静态分析，都能做到底层Pretext 等项目覆盖的语言和边界情况极多，用于生产前需要自行评估
设计对交互细节有近乎偏执的要求，并且能讲清楚为什么个人网站是作品集而非介绍页，初次访问者不易了解他的经历
AI 时代率先公开用 Claude Code、Codex 写底层库，并给出可验证的方法部分新项目（handwired、sotaku）仍是实验性质

可以从他身上学什么

  • 从感受出发做底层：先找到用户感受得到的不顺，再回头改造基础设施。
  • 把细节写下来：chenglou.me 的 README 把「顺」拆成一条条可以复用的做法。
  • 为基础设施做演示：好的演示让一个排版库变得人人都看得懂。
  • 让 AI 有据可依：先准备好可自动对照的真值，再让 AI 迭代。
