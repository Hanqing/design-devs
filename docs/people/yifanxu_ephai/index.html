当十几个编程 Agent 同时改同一个项目，它们需要各自的工作区，又不能每人复制一份完整的仓库。LayerFS 的答案是：每个 Agent 在共享的已提交历史之上挂载一个完整、可写的工作区，干完活提交改动，然后工作区消失。计算只在命令运行时存在，历史永远留下来。

TA 到底在做什么？

Yifan 在做并行 Agent 的底层基础设施。LayerFS 的四个核心想法是：短暂计算，计算只在命令运行时存在；去中心化 Agent，不同电脑上的 Agent 共享一个无服务器的 Store；多 Agent 协调，一个项目多个分支、一个分支多个 Agent，冲突的提交会被拒绝；递归文件系统，可以在任意深度从任意提交瞬间分叉。

目前 LayerFS 通过 DeepSeek Harness 的 dsh-layerfs 插件使用：会话里的 Agent 可以分叉分支、在沙箱里测试、合并发布，Work 和 History 标签页实时显示每个 Agent 的分支。

代表作品详解

LayerFS ↗

2026RustMIT · v1.0.0

「LayerFS is the substrate under your agents.」每个 Agent 挂载一个在共享已提交历史之上的完整可写工作区，做完工作、提交改动、然后消失。支持 Linux，macOS 通过 DSH 使用。

README 写得很坦诚：Store 目前只运行在 Disposable 配置下，没有崩溃和断电持久性，「把 LayerFS 用于 Agent 的工作和它的历史，而不是作为你无法重建的数据的唯一副本」。

设计观点

Use LayerFS for agent work and its history, not as the only copy of data you cannot rebuild.

— LayerFS README

LayerFS 的思想和 Git 一脉相承，但被下沉到了文件系统层，让 Agent 不需要理解 Git 也能安全地并行工作、分叉、合并。
