他到底在做什么？

Emil 的专长是让界面「感觉对」：缓动曲线、时长、手势阻尼、交错动画这些细节。Sonner 是他把这些细节打包成一个组件的结果：通知可以堆叠、展开、滑动关闭，往上拖时不会被直接拦住，而是感到「摩擦」。

这两年他把同样的经验教给 AI：Skills 仓库里有 /animate、/review-animations、/animation-performance、/mobile-native、/break-ui 等指令，让编程 Agent 在动效和交互上少犯常见错误。他在 Linear 的最后几个月里，用大约一百万 token 把 Linear 的组件从 Radix 迁到了 Base UI。

AI doesn’t replace such expertise, it amplifies what you can get out of it.

— Emil Kowalski，Skills 仓库 README

他在 X 上的观点很具体：越大的元素动得越慢，因为它「感觉更重」；元素多时要交错出场；长文用 18 到 20 像素字号更好读；text-wrap: pretty 应该全局默认打开。他也对「一天发几百个 PR」的说法表示怀疑：为什么需要发那么多？

可以从他身上学什么

  • 先问要不要动：很多地方根本不需要动画。
  • 动画要符合物理直觉：大的慢，小的快，多的交错。
  • 组件的价值在默认值：别人直接用就该是好的。
  • 给自己造工具：调动画、看性能、填测试数据都值得做个小工具。
  • 失败一次不算什么：面试没过，十个月后再来。
