Jake Archibald：没有一个想法不发表

他住在英国西萨塞克斯郡的海沃兹希斯，X 简介写着「Firefox 的某种开发者。没有一个想法不发表。He/him。」他在 Google Chrome 开发者关系团队工作了很多年，是 Service Worker 和离线优先（offline-first）理念最重要的推动者之一：他参与编写 Service Worker 规范，做了跟踪各浏览器支持进度的「Is ServiceWorker ready?」，写了经典文章《The offline cookbook》。他做的工具很多人每天都在用：SVG 压缩工具 SVGOMG（★6.2 千）、把 IndexedDB 包装成 Promise 的 idb（★7.4 千）和 idb-keyval，以及和同事一起做的图片压缩应用 Squoosh。他和 Surma 主持的视频节目 HTTP 203 也很受欢迎。现在他在 Mozilla 做 Firefox 和 Web 标准，2026 年他写了大量关于图片格式、CSS 细节和无障碍的深度文章。

10.8 万X 关注者
2008加入 X

2026 年 10 月，JPEG XL 终于进入了 Web，他写了一篇《JPEG XL vs AVIF for web use-cases》做全面对比。接着他在 X 上批评了一些「JPEG XL 话语里的不诚实」：为什么拿一个 25 年前的格式做对比，而不是更现代的格式？为什么宣称支持 HDR，却不说清楚增益图（gain map）这个关键部分？他的结论是 AVIF 更适合 HDR，因为源文件可以是 10 位，而且浏览器里 JPEG 和 AVIF 都支持增益图，JPEG XL 不支持。他还为 Interop 2027 提议把「渐进式图片渲染」列为重点，让 Safari 支持渐进式 JPEG XL，让 Safari 和 Firefox 支持渐进式 AVIF。

他到底在做什么？

Jake 现在在 Mozilla，一边做 Firefox，一边推动跨浏览器的互通：在 CSS 工作组讨论把自定义 <select> 的合理尺寸写进默认样式表，参与 Interop 年度重点的投票（他说比起在 GitHub issue 上点赞，这种方式更难被刷）。

他的文章以极度认真著称：一篇讲清楚 CSS 自定义属性到底在什么时候计算，一篇复盘自己在提示框上犯的无障碍错误（aria-describedby 并不总是够用），一篇研究自定义 select 的「刚刚好」高度，一篇比较 import 和 fetch JSON 的差别。他还试验过「响应式代码」：构建脚本用 Prettier 为每段代码生成最多 5 个版本，再用容器查询显示合适的那个。
