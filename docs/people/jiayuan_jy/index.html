TA 到底在做什么？

Multica 想回答的问题是：一个小团队到底该怎样和 AI Agent 一起把事情做完？它的答案不是一个新的聊天框，而是团队已经熟悉的东西：Issue、状态、指派、评论、动态流。只不过参与者里多了 Claude、Codex 这样的 Agent，它们会领任务、汇报进度、提出阻塞、交回审查。

官网 About 页的判断很直接：「有了合适的系统，两名工程师加上一组 Agent，就能发挥出二十人团队的推进速度。」

本页依据 Multica 官网与 About 页、GitHub、TA 的博客与 Indie Hackers 文章整理，资料截至 2026 年 10 月。TA 在 TikTok 的具体工作未见公开细节。

代表作品详解

Multica ↗

2026.01Go + TypeScript源码公开 · 可自托管

「Agents that show up on the board.」在 Multica 里，你像给同事派活一样把 Issue 分配给 AI 编程 Agent：它领走任务，把状态从 Todo 改成 In Progress，在评论里汇报进展（官网演示里，Claude 说「我已经统一了 14 个处理器的错误响应，PR #43 等待审查」），遇到阻塞就提出来，做完交还给人审查。

它不替代你已经在用的工具，而是把它们接进来：Claude Code、Codex、Cursor、GitHub Copilot、Antigravity、Qwen Code、Kimi CLI、DeepSeek Harness、Trae、OpenCode 等 20 多种。

  • Agent 是一级成员：有个人档案、会报告状态、创建任务、发表评论。
  • 技能会积累：官网标语是「分配任务、跟踪进度、积累技能」。
  • 数据在你手里：源码公开，可免费自托管，工作区数据保存在自己的基础设施上；商业使用规则写在授权说明里。

andrej-karpathy-skills ↗

2026.01一份 CLAUDE.md★22 万

一份根据 Andrej Karpathy 对大模型编程陷阱的观察写成的 CLAUDE.md。Karpathy 抱怨模型会替你做错误假设然后一路跑下去、喜欢把代码和 API 搞复杂、会顺手改掉自己不理解的注释和代码。这份文件用四条原则回应：

Think Before Coding（不假设、不隐藏困惑、说清取舍）、Simplicity First（拒绝过度抽象）、Surgical Changes（只改该改的地方）、Goal-Driven Execution（先写测试、设定可验证的成功标准）。

TA 的观点有一条清楚的主线：用熟悉的形式承载新的能力。写作上，用 Twitter thread 替代难写的长博客；产品上，用 Issue 和看板替代新的聊天界面；方法上，用一份简单的 CLAUDE.md 替代复杂的工具。

长处与局限

维度长处局限 / 需要留意
分发X 上长期积累的读者，让产品发布自带流量高度依赖单一平台
产品用熟悉的协作隐喻降低理解成本；开源可自托管是「源码公开」而非传统开源许可，商业使用需看授权说明
团队小团队合作多年，执行力强Agent 协作平台赛道拥挤，差异化需持续证明
影响力一份 CLAUDE.md 获得 22 万星爆款说明书的热度不等于产品本身的采用度

可以从 TA 身上学什么

  • 用熟悉的隐喻承载新能力：Agent = 同事，Issue = 任务。
  • 低成本地持续写作：先在 thread 里写，好的内容再沉淀成长文。
  • 一份好说明书也能出圈：在 Agent 时代，清楚的规则可能比复杂的产品传播得更快。
  • 开源换信任：可自托管、源码可见，降低企业采用门槛。
