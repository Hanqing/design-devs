他没有独立的个人网站，X 是他的主要阵地。Multica 官网就是他目前的名片：一个模拟的 Issue 页面展示「Alex 把任务分配给 Claude，Claude 把状态改为进行中」，非常直观地讲清了产品理念。

设计与思考

Multica 的设计核心是一个隐喻：像给同事派活一样给 Agent 派活。不是新的聊天框，而是已有的协作习惯（Issue、状态、评论、动态流），只是参与者多了 Agent。

andrej-karpathy-skills 的巨大成功也说明了他的嗅觉：在 Agent 时代，「一份好的说明书」可能比一个复杂的产品传播得更快。

可以从他身上学什么

  • 用熟悉的隐喻承载新能力：Agent = 同事，Issue = 任务。
  • 在 X 上持续输出：长期分享让创业有了天然的分发渠道。
  • 快速做 MVP：一周做出可用版本，再根据反馈演进。
  • 开源换信任：可自托管、源码可见，降低企业采用门槛。
