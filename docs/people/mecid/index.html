Majid 的文章有一个固定的开头：先抛出一个真实问题，比如「一个页面需要 40–50 个异步请求才能填满，怎样安排这些请求才不会压垮协作线程池？」，然后是一句「This week, we will talk about…」（这周我们来聊聊……）。七年下来，这个节奏让很多读者养成了每周读 Majid 的习惯。

TA 到底在做什么？

Majid 的工作是一个写作与产品互相喂养的循环。CardioBot 需要几十个 HealthKit 查询，于是有了《Iterative data loading in Swift》；需要画心率图表，于是有了支持 VoiceOver 的 SwiftUICharts；苹果推出 Foundation Models，PlatePal 就用上了多模态输入，文章也随之而来。

TA 的 App 都在健康领域：CardioBot 把 Apple Watch 的心率、心率变异性、压力、恢复、睡眠和活动数据变成清晰的个性化健康洞察；NapBot 用设备端机器学习自动追踪睡眠；PlatePal 拍一张餐盘照片，帮你理解分量和饮食平衡，「不数卡路里、不算宏量营养素、没有数字」。

本页依据 Swift with Majid（含 About 与文章）、GitHub、App Store 整理，资料截至 2026 年 10 月。About 页上的个人联系方式未收录。

长处与局限

维度长处局限 / 需要留意
写作七年每周一篇，覆盖几乎所有 SwiftUI 新 API文章篇幅偏短，侧重 API 用法，深度架构讨论较少

节奏持续跟进苹果平台的每一次变化—

可以从 TA 身上学什么

  • 固定节奏：每周一篇，七年不断，就是一份事业。
  • 从产品中提炼文章：真实问题写出来的内容最有用。
  • 重视无障碍：图表库也要支持 VoiceOver。
  • 把 bug 最小化再报告：对平台和社区都有帮助。
