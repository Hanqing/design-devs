她到底在做什么？

Lauren 的工作有两条并行的线。一条是基础设施：在 Meta 时她带头原型化 Server Components 并接入 Relay，后来投入 React Compiler（原名 React Forget），让组件和 Hook 在构建时被自动记忆化，开发者不用再手写 useMemo、useCallback 和 React.memo。

另一条是「整理与分享」：为没能到场的人汇总 EmberConf、ElixirConf、RustConf 的全部演讲和资料；把「不做白板算法题面试的公司」列成清单；2026 年又把自己用 AI Agent 的方法写成一组 Skill 开源出来。

本页依据 no.lol 博客、GitHub、react.dev 博客、React Conf 讲者介绍和各项目 README 整理，资料截至 2026 年 10 月。她在 Cursor 和 xAI 的具体工作内容未见公开细节，因此只写 GitHub 组织和 X 简介可以核实的部分。

代表作品详解

React Compiler ↗

2024 Beta → 2025 1.0核心团队构建时优化

在 React 里，组件每次重新渲染都会重新计算所有值、重新创建所有函数。为了避免不必要的工作，开发者需要手动包上 useMemo、useCallback 和 React.memo，并且维护正确的依赖数组，稍有不慎就会出 bug 或者白忙一场。

React Compiler 在构建时分析组件和 Hook 的数据流，自动插入记忆化，让「默认就快」成为新常态。官方文档为它准备了渐进式接入、调试排错、编译库等完整指南，并有一个 React Compiler 工作组公开讨论设计。

hiring-without-whiteboards ↗

2017社区清单★52,826

「Companies that don't have a broken hiring process.」收录不做「白板」面试的公司和团队。README 特意说明：白板只是一个比喻，「白板本身不坏，坏的是计算机科学冷知识题」；LeetCode、HackerRank 式的考察大概也属于同一类。被收录的公司使用贴近日常工作的方式，比如结对解决真实问题，或者布置带回家的作业。

这个仓库至今仍在接受社区更新，还附有一份「如何改进面试」的建议文档。它是她作为管理者思考招聘的副产品，也是 GitHub 上最知名的招聘类仓库之一。

how · noodle · brainmaxxing ↗

2026Agent 工具Cursor / Claude Code

三个小工具，代表了她怎样把工程习惯交给 Agent：

  • how（★916）：一个 Cursor 插件，提供 /how 技能。问「某个子系统怎么工作」，Agent 会像资深工程师入职新领域一样，给出概览、关键概念、工作原理、代码位置和坑点。复杂问题会拆成 2–4 个方向并行探索，再由一个综合 Agent 合并结论；「批评」模式还会召集多个不同模型的独立评审来找架构问题。
  • noodle（★526，Go）：基于 Skill 的 Agent 编排工具。安装方式本身就很有代表性：把一句「按这个文件的说明安装」交给你的 Agent。
  • brainmaxxing（★342）：「简单到傻」的 Claude Code 持久记忆。一个 Markdown 库（同时也是 Obsidian 库），Agent 在会话开始时读、学到东西时写；附带 16 条工程原则和 reflect、ruminate、meditate、plan、review 等技能，形成「复盘—反刍—审视—修剪」的学习循环。
  • verification-skill-example（★160）：一个虚构的大型桌面应用的「验证技能 + 功能地图」示例。README 里的一句话很精辟：wiki 适合人看，但「Agent 每重读一个 token 都要付费」，所以应该给它按功能拆分、可执行的地图。

pstack ↗

2026Grok Bot 插件Cursor Marketplace

「if you want to go fast, go deep first.」（想要快，先要深。）pstack 是一套严谨的 Agent 工作流，目标是「写更少但质量更高的代码」，并且可以放心地并行运行。它以 Grok Bot 插件的形式发布在 Cursor Marketplace 上，X 简介里她称自己正在用它交付工作。

可以从她身上学什么

  • 把知识编进工具：与其写文档教大家用 useMemo，不如让编译器自动完成。
  • 为社区做整理：会议总结、公司清单这类「整理型开源」同样能影响几万人。
  • 给职业选择设一个复盘点：每年问自己一次「这还是我的理想角色吗」。
  • 给 Agent 写地图，而不是 wiki：按功能拆分、可以直接执行，节省 Agent 的每一个 token。
  • 先深后快：在 Agent 时代，深入理解问题依然是速度的前提。
