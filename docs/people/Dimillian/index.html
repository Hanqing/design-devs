TA 到底在做什么？

Thomas 的开源有一个固定模式：新技术一出来，就用它做一个完整的、能上架的 App 开源出来。Swift 发布当月，TA 写了 Hacker News 阅读器 SwiftHN；SwiftUI 发布当月，写了带自定义 Redux 的 MovieSwiftUI；Mastodon 爆发时，写了 Ice Cubes；Bluesky 起来时，开始写 IcySky。这些代码库成了很多人学习 SwiftUI 架构的范本。

加入 OpenAI 之后，TA 把同样的方式用到了 Codex 上：CodexMonitor 用来同时编排多个 Codex Agent，Codex Skill Manager 用来管理本地的 Codex 和 Claude Code 技能，Skills 仓库则公开了自己的日常技能。

本页依据 dimillian.app（About、Talks、Articles、Open Source）、GitHub 与项目 README 整理，资料截至 2026 年 10 月。TA 在 Google 的具体工作未见公开细节。

从 SwiftUI 到 Codex，TA 始终站在同一个位置：新工具如何被开发者真正用起来。SwiftUI 时代是写出完整的参考 App；AI 时代是写工作流文章、公开自己的 Agent 配置、做管理工具。

长处与局限

维度长处局限 / 需要留意
开源完整、可上架的 App 代码库，学习价值极高部分早期项目（MovieSwiftUI 等）已不再积极维护
时机总是第一批用新技术做出作品追新带来的项目多，有的停留在「TBD」状态（如 IcySky）
影响力从社区布道走到 OpenAI 负责开发者体验在 OpenAI 的工作以团队成果为主，个人贡献边界不易看清
表达文章、演讲、开源三线并进博客文章分散在 Medium 等多个平台

可以从 TA 身上学什么

  • 开源一个完整 App：比写十篇教程更有说服力。
  • 新技术发布当天就动手：Swift、SwiftUI、Mastodon、Codex，每次都很快做出作品。
  • 做自己会用的工具：动森助手、Codex 监控，都是自用需求。
  • 把兴趣变成职业：开源影响力最终把 TA 带到了 OpenAI。
