Tim Neutkens：让 Next.js 更快一点

他来自荷兰，是 Next.js 的联合作者之一，在 Vercel 工作。他的个人网站只写了一句：「你可能知道我是 Next.js 的作者之一，一个基于 React 的流行开源 Web 开发框架。」据维基百科，Next.js 2016 年 10 月 25 日在 GitHub 开源，如今被沃尔玛、Apple、Nike、Netflix、TikTok 等大量网站使用。除了 Next.js（★14.3 万），他还是「组件时代的 Markdown」MDX（★2 万）、异步 HTTP 微服务框架 Micro（★1.1 万）和把 Node.js 项目编译成单个文件的 ncc（★9.8 千）的联合作者。早年他写 PHP 和 WordPress 工具。2026 年，他带着团队发布了 Next.js 16.3，把开发环境下 React Server Components 的渲染时间最多减少 73%，并在一次清理中关闭了 1,500 个重复、已修复或无法复现的 issue。

2026 年 7 月，他发帖解释了一个不起眼却很有效的优化：很多框架（包括 Next.js）在开发环境下会提高 JavaScript 的堆栈跟踪深度，这样深层代码或 node_modules 里出错时能看到完整的调用栈。但这在 V8（比如 Node.js）上有代价。基于团队前一年在 React.jsx 里的类似发现，他们把开发环境下 React Server Components 的渲染时间最多减少了 73%。他特别感谢了最初做这项研究的同事。

他到底在做什么？

Tim 现在的重心是Next.js 的性能和开发体验：16.3 版本带来了「即时导航」和配套的洞察收集，开发者工具里新增了 Request Insights 标签，可以直观看到单个请求的时间花在了哪里。团队还分析了用户分享的真实仪表盘应用，从中找到了包括 React 在内的多处性能问题。

他也在改进开源维护本身：2026 年 9 月，Next.js 团队用一套系统化的调查和复现流程，一次性清理了 1,500 个 issue，减少重复报告和已失效的问题。8 月，团队在 Reddit 上做了一次公开问答。
