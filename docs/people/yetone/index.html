yetone：把 AI 塞进终端和菜单栏的人

从一个 Bob 翻译插件，到 GitHub 上数万星的 openai-translator、avante.nvim 和 magpie。yetone 的作品几乎都在回答同一个问题：怎样让 AI 不打断开发者原本的工作流。

一句话：一个前后端、云原生都写过的工程师，最擅长的是给开发者做工具，而且几乎每次都踩在 AI 浪潮的正确时间点上。

代表作：openai-translator（2023）、avante.nvim（2024，让 Neovim 拥有 Cursor 式体验）、magpie（2026，为每个 Agent 切换模型的本地网关）。

为什么值得关注：他的作品不是「又一个聊天框」，而是把 AI 嵌进你已经在用的地方：划词翻译、编辑器、终端、菜单栏。

yetone 在 2010 年注册 X，2011 年注册 GitHub，个人简介只有一个词「ohh」。比起写长文介绍自己，他更习惯直接把东西做出来：一个能用、好看、顺手的工具，往往就是他的自我介绍。

成长与经历

yetone 在 GitHub Stars 的自我介绍里写道，他做过前端、后端和云原生开发，最喜欢的是给开发者做工具，并且是终端、键盘驱动工作流的忠实拥趸，尤其偏爱 TUI。这几句话几乎可以解释他后来所有的作品。

  1. 2010–2011

    注册 X 与 GitHub

    早期在 GitHub 上留下的大多是 Vim 配置、小工具与各种实验，属于典型的「工具控」路线。

  2. 2022

    cosmos-nvim：从 Spacemacs 叛逃到 Vim

    为从 Spacemacs 迁移到 Neovim 的用户准备的一套配置。它是后来 avante.nvim 的伏笔：他对编辑器体验的要求一直很高。

  3. 2023

    openai-translator 与 Bob 插件

    ChatGPT API 刚开放时，他先写了一个 macOS 翻译软件 Bob 的插件，用大模型做划词翻译、润色和语法纠错；随后又做成跨平台的桌面端与浏览器扩展，迅速成为当年增长最快的中文开源项目之一。

  4. 2024

    avante.nvim：Neovim 里的 Cursor

    2024 年 8 月开源。它把 Cursor 那种「AI 建议 → 一键应用 diff」的体验搬进 Neovim，后来又支持 Agent 模式和 ACP（Agent Client Protocol）。这是他在 GitHub Stars 里自己列出的代表作。

  5. 2025

    Alma 与一系列 AI 桌面应用

    Alma 是一个统一多家模型提供商的 AI 桌面客户端；同时期还有 Confirmo（住在桌面上的 AI 编程伙伴）、Yansu（主动式 AI）等实验。

  6. 2026

    magpie、cumora 与更多

    magpie 让 Codex 用 DeepSeek、Claude Code 用 Kimi，只需在菜单栏点一下，上线后很快拿到近两万星；cumora 是「人和 AI Agent 同为队友」的团队聊天应用；他还发布了 kill-ai-slop、native-feel-skill 等关于产品质感的 Agent Skill，甚至做了一个南宋背景的网页动作游戏《劍》。

个人网站与线上形象

github.com/yetone ↗

yetone 没有传统意义上的个人博客，他的 X 主页就是作品目录：Built 一行写着 avante.nvim，Building 一行列出 magpie、Alma、Confirmo、剑、Yansu、Cumora 六个链接。

GitHub 个人简介只有「ohh」两个字母加一个感叹词；公司一栏写着 @Isoform。

他的产品官网非常统一：大标题一句话讲清价值（「Every agent's model. One place.」），下面紧接一张清晰的数据流示意，再往下是多语言切换和下载按钮。magpie 的官网同时提供英语、中文、日语、德语四种语言，这在个人开发者里并不常见。

设计与手艺

yetone 的作品有一个共同的「不打扰」哲学：工具应该长在你原本的工作流里。翻译出现在划词的位置，AI 建议出现在编辑器的 diff 里，模型切换出现在菜单栏。用户不需要学会一个新应用，只需要多一个顺手的入口。

他也在认真思考 AI 时代的「质感」问题。kill-ai-slop 把 AI 生成界面里常见的渐变紫、空洞形容词、过度 emoji 等「slop」列成清单；native-feel-skill 研究的是怎样让 Electron/跨平台应用摸起来像原生。这说明他关心的不只是功能能不能跑通，还有东西用起来好不好。

一个值得学的细节

magpie 改写 Agent 配置时「只改你动过的那个键」，选回原生模型时「把原来的东西原样放回去」。这类细节很少出现在宣传语里，却决定了一个工具敢不敢被装进别人的主力环境。

可以从他身上学什么

  • 站在时间点上：新能力出现时（ChatGPT API、Agent、ACP），第一时间把它接进开发者最常用的入口。
  • 先做插件，再做产品：openai-translator 从一个 Bob 插件起步，验证需求后才扩展成跨平台应用。
  • 尊重用户的现有配置：只改必要的部分，可逆、可回退，这是开发者工具赢得信任的前提。
  • 把审美写成规则：把「什么是 slop」「什么是原生感」写成 Skill，让好品味可以被复用。
