TA 到底在做什么？

yetone 做的东西可以分成三层。最底层是「胶水」：把模型接到开发者已经在用的地方。划词翻译接到 Bob 和浏览器里，AI 编程接到 Neovim 里，任意模型接到任意编程 Agent 里。中间一层是「新形态的应用」：多模型聊天客户端 Alma、住在桌面上的编程伙伴 Confirmo、人和 Agent 同为队友的团队聊天 Cumora。最上层是「审美」：把什么是 AI 陈词滥调、怎样做出原生手感写成可复用的 Agent Skill。

和很多「一次性爆款」不同，TA 的项目有很强的延续性。nextai-translator 和 avante.nvim 都持续维护了两年以上，并且都从个人仓库搬进了独立的组织，交给社区一起维护。

本页依据 GitHub、GitHub Stars 个人页、各产品官网与 README 整理，资料截至 2026 年 10 月。yetone 没有公开的个人博客，也没有找到可信的长篇采访，因此早年经历只写 TA 自述和 GitHub 上可以核实的部分。

代表作品详解

magpie ↗

2026.09Go免费 · 开源

口号是「Every agent's model. One place.」解决的问题很具体：Codex 只认 OpenAI Responses 协议，Claude Code 只认 Anthropic Messages 协议。magpie 在你电脑上（127.0.0.1:3425）跑一个本地网关，同时会说这几种协议并且双向翻译，流式输出、工具调用和推理过程都不丢，于是任意 Agent 都能用任意厂商的模型：Codex 用 DeepSeek，Claude Code 用 Kimi，Gemini CLI 用 GLM。

真正让它出圈的是几个细节：

  • 菜单栏一键切换：只改写那个 Agent 配置里你动过的那一项；选回原生模型时，把原来的配置原样恢复。
  • 订阅共享：在 Claude Code 里登录过的 Claude Pro / Max、在 Codex 里登录过的 ChatGPT Plus、你的 Copilot 席位，都能变成其他 Agent 的模型来源，不用复制或粘贴任何密钥。
  • 智能路由：给每个模型写一句用途（「简单提问」「写或修测试」），每轮对话开始时由一个小模型判断类别，再交给对应的模型。
  • 自动接力：多个账号和密钥都加进来后，某个额度用完，下一个会在 Agent 报错之前接上。
  • 覆盖面：官网列出 30 多个支持的 Agent（Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI、Copilot CLI、Goose……）和 15 家以上模型供应商；提供中、英、日、德四种语言。

avante.nvim ↗

2024.08Lua + RustApache 2.0

「Use your Neovim like using Cursor AI IDE!」侧栏对话、AI 建议以 diff 形式预览、一键应用到源文件。之后陆续加入项目级指令文件（avante.md）、多家模型供应商、Agent 模式，以及 2025 年 9 月的 ACP 支持，让 Neovim 可以直接驱动外部的编程 Agent。

它的意义在于证明了「终端党」不必为了 AI 离开自己的编辑器。项目后来搬到了 avante-corp 组织下，周边已经长出第三方生态，比如为它做本地 OpenAI 兼容代理的 PyPI 包。

nextai-translator（原 openai-translator） ↗

2023.03TypeScript + Rust浏览器扩展 + 桌面端

「不只是翻译的翻译器」：划词翻译、润色、总结、语法纠错，背后接的是大模型。最早是 macOS 翻译工具 Bob 的插件，验证需求后扩展成 Chrome / Firefox 扩展和跨平台桌面端。为了能在任何应用里取到选中文字，TA 还单独抽出一个 Rust 库 get-selected-text（★210），支持 macOS、Windows、Linux。

Cumora ↗

2026.08TypeScript预览期免费

「A workspace where AI teammates live, not visit.」一款人和 AI Agent 同为成员的团队聊天应用：同一份成员列表、同样的私聊和群聊、同一块看板和日历。每个 Agent 有自己的人设、记忆和状态，能认领任务、互相协调、收发真实邮件，可以跑在 Cumora 云端，也可以用你自己的 Claude Code / Codex 作为「大脑」。

最特别的设计是「主动性」：按你设定的节奏，空闲的 Agent 会醒来看看房间里发生了什么，再决定要不要私信某个队友、发一条想法，或者拉几个人讨论它注意到的事。

观点与方法

I firmly believe that only keyboard operations can form muscle memory.

— yetone，GitHub Stars 个人页

从作品里能读出 TA 的几条原则：

  • 入口比功能重要。翻译出现在划词的位置，AI 建议出现在编辑器的 diff 里，模型切换出现在菜单栏。用户不需要学会一个新应用，只需要多一个顺手的入口。
  • 尊重用户的配置。magpie 只改你动过的那一个键，可以完整回退。开发者工具只有做到可逆，才敢被装进别人的主力环境。
  • 质感可以被写下来。与其每次都靠感觉，不如把「什么是 slop」「什么是原生感」写成规则，让 Agent 也能遵守。
  • Agent 是同事，不是聊天框。从 Confirmo 的桌面伙伴到 Cumora 会主动开口的队友，TA 一直在探索 Agent 更自然的存在方式。

长处与局限

维度长处局限 / 需要留意
时机对新能力极其敏感，常常是第一批做出可用接入层的人追热点的项目更新快，用户需要跟上频繁的版本变化
工程多语言、多平台通吃；项目能长期维护并交给组织产品线越来越多（magpie、Cumora、Alma、Confirmo……），精力如何分配有待观察
设计重视可逆性、原生感和文案，主动反思 AI 产品的审美问题部分桌面应用（如 Alma）官网写明只在 Apple Silicon 上充分测试
商业开源 + 赞助 + 商业赞助位，路径清楚多数产品免费或处于预览期，长期收费模式尚未公开
以上判断基于公开资料，不是对软件质量的实测结论。

可以从 TA 身上学什么

  • 站在时间点上：新能力出现时，第一时间把它接进开发者最常用的入口。
  • 先做插件，再做产品：openai-translator 从一个 Bob 插件起步，验证需求后才扩展成跨平台应用。
  • 把底层能力抽成库：get-selected-text 这样的小库，既服务自己的产品，也让别人受益。
  • 成功之后交给社区：把项目迁入独立组织，让它不依赖某一个人。
  • 把审美写成规则：native-feel-skill 和 kill-ai-slop 让好品味可以被复用。
