Shu DingVercel 工程师 · Next.js 核心维护者 · SWR、Satori、Nextra、COBE 作者 · v0 联合创造者

Shu Ding：不能让沉默更好，就别开口

他高中起就参加算法竞赛、做网页设计和开发，2017 年从复旦大学计算机系毕业，进入微软做软件工程师；2018 年作为最早的一批工程师加入 Vercel（当时叫 ZEIT），参与核心平台、Next.js、AI SDK 和 v0。2019 年他和 Guillermo Rauch 一起做了 SWR，第一个基于 Hook、「先返回缓存再重新验证」的数据请求库；2020 年起他是 Next.js 的核心维护者，主导了流式 SSR、Edge Runtime、React Server Components 和 Server Actions 的开发。他还写了不需要浏览器就能把 HTML 和 CSS 渲染成 SVG 的 Satori（已成为各大框架生成社交分享图的标准做法）、只有 5 KB 的 WebGL 地球 COBE，以及 Next.js 文档框架 Nextra。

2022 年，Shu 为了让 Vercel 博客的标题换行更好看，写了一个小组件 React Wrap Balancer，后来又被移植到 Vue 和 Svelte。他在个人网站上写道：「我相信它推动了 CSS 标准 text-wrap: balance 的出现。」这就是他的风格：从一个具体的页面需求出发，做一个很小的东西，最后影响整个生态。

他到底在做什么？

Shu 同时站在框架架构和图形渲染两端。在 Next.js 里，他和 React 团队紧密合作，主导了服务端渲染的一系列架构升级。在 Vercel，他做了快速图片生成、分析图表的曲线拟合、控制台性能优化；2023 年他和 Jared Palmer、Max Leiter、shadcn 一起做出 v0，参与设计架构，实现了核心 AI、流式渲染管线和 Design Mode。

2026 年他在做两类实验。一类是小模型：GPU Lexer 用神经网络和 WebGPU 在浏览器里做语法高亮，「如果把源代码的每个词当成像素，语法高亮本质上就是一维图像的分割」；很快社区就跟进了一批 gpu-* 小模型库。另一类是纯 CSS：既然 HTML/CSS 是图灵完备的，为什么不把程序编译成零 JavaScript 的网页？这延续了他 11 年前的学校项目 css-computer。

代表作品详解

SWR ↗

2019–React Hooks★3.2 万

名字来自 HTTP 缓存策略 stale-while-revalidate：先返回缓存数据，再在后台请求，最后更新。它是第一个基于 Hook 的这类数据请求库。Logo 由 Evil Rabbit 和 Paco Coursey 设计。

Satori ↗

2021–HTML/CSS → SVG★1.4 万

「第一个不需要浏览器的 CSS 到 SVG 渲染引擎」，为 Vercel 的 OG 图片生成而写，现在是 Next.js、Nuxt、SvelteKit、Astro 生成社交卡片的通用方案。2026 年 10 月他预告了下一版：支持 grid、定位、浮动、计数器、混合模式等大量 CSS 特性，宣传视频的每一帧都由 Satori 渲染。

COBE ↗

2021–WebGL★6 千

可能是网页上最小的 3D 地球（约 5 KB），最初是为了加快 Vercel 首页的加载速度。任何 DOM 元素都可以作为标记点绑定上去，CSS 过渡、动画、滤镜都能正常工作。

Don’t talk unless you can improve the silence.

— Shu Ding，X 简介

面对 GPU Lexer 引来的批评，他的回应很坦率：「也许这是个蠢主意。它是实验性的，不打算用于生产，也不打算取代现有工具。」这种「先做出来再讨论」的态度贯穿了他的大部分开源作品。

可以从他身上学什么

  • 从真实页面出发：Wrap Balancer 来自博客标题。
  • 小体积就是功能：5 KB 的地球比 3D 库好用。
  • 换个视角看老问题：语法高亮也可以是图像分割。
  • 写一份作品史：每个项目写清贡献和影响。
  • 少说话，多做东西。
