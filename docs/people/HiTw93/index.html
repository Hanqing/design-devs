Pake、MiaoYan、Mole、Kaku、Waza、Kami……一位杭州的产品工程师，每逢春节、国庆就写一个新项目，十年下来攒出 18 万 GitHub 星；周刊写到第 286 期；2025 年在三亚泳池边写的几百行 Shell，变成了 7 万星的 Mole 和 TA 的第一个付费产品。

一句话：来自杭州的产品工程师，「做简洁好用的小工具让生活更简单」。前端出身，在阿里做过 Weex、XRender 和 iOS 业务，后来用 Rust、Swift、Shell 做出一串中文开发者圈最知名的开源工具。

代表作：Mole（Mac 清理与系统工具，★7.2 万）、Pake（一条命令把网页变桌面应用，★6.2 万）、Kami（让 Agent 输出精美文档，★1.2 万）、MiaoYan 妙言（★8.7 千）、Waza、Kaku。

TA 到底在做什么？

Tw93 同时在做三件事。第一是开源工具：几乎每个长假写一个，春节写了 MiaoYan 和 Kaku，国庆写了 Pake，2025 年国庆前写了 Mole。每个项目都有多语言 README，大多数在发布后持续维护多年。

第二是写作：一个更新极勤的周刊（每周一一期，封面是自己拍的照片），和一个以「你不知道的 ×××」为题的长文博客，2026 年系统写了 Claude Code、Agent、大模型训练、GEO、具身智能。第三是第一次认真做付费产品：Mole for Mac。TA 把这三个月学到的东西写成了一篇很少见的、诚实的独立产品复盘。

本页依据 tw93.fun（含关于页与博客）、潮流周刊、mole.fit、GitHub 与各项目 README 整理，资料截至 2026 年 10 月。

成长与经历

  1. 2014–2015

    从前端开始

    GitHub 账号 2014 年注册。博客存档始于 2015 年，最早的文章是《JavaScript 的数据访问性能优化》和 Vue、Angular、Avalon 的框架比较；同年用 Node.js + Express + MongoDB 写了一个电影网站练手。

  2. 2015–2016

    前端基本功

    把《JavaScript 设计模式》读两遍写笔记，研究 Flexbox、React Native 动画、Generator 与 Channel。文章习惯用「提出问题、论证问题、解决问题」的结构。TA 后来回忆，学会前端之后第一个特别想学的是 WebGL。

  3. 2017–2018

    Weex、双十一与 iOS

    在阿里分享《Hello Weex》，做了 Weex Ui 组件库；为排查双十一期间的 Weex 性能问题开始学 iOS，2018 年正式参与 iOS 业务开发。GitHub 上至今挂着 alibaba 和 apache 两个组织（Weex 后来捐给了 Apache 基金会）。

  4. 2019

    XRender

    参与并主导阿里开源的中后台表单 / 表格 / 图表方案 XRender。它三岁时，TA 用 gource 和 ffmpeg 把仓库历史渲染成视频，「给代码祝寿」。

  5. 2020 春节

    妙言 MiaoYan

    给工程师用的原生 macOS Markdown 写作应用。两年后重新打磨开源，成为 TA 最受欢迎的 Swift 项目。

  6. 2021–2022

    《潮流周刊》

    每周记录看到的好东西和生活。第 100 期时自己用 Astro 设计开发了官网；第 268 期写道，这份周刊已写了近六年，全部手写，不用 AI。

  7. 2022 国庆

    Pake

    用 Rust + Tauri 把任意网页打包成几 MB 的桌面应用，一条命令搞定。发布后迅速走红，至今 fork 数超过 1.2 万。

  8. 2025 国庆前

    Mole

    在三亚泳池边写了几百行 Shell，做出命令行清理工具 Mole；之后长出原生 Mac 客户端，一次买断 19 美元，是 TA 的第一个付费产品。

  9. 2026

    Kaku、Waza、Kami 与一个小机器狗

    春节写了 AI 友好的终端 Kaku，春天写了 Waza 和 Kami；4 月用 STM32、ESP32-C3、舵机和 3D 打印件手搓了一台能听懂话、能接云端 AI 的小机器狗；5 月开始做一款面向纸面排版和长文阅读的中文字体「落文」。

这条路的特别之处在于节奏：大公司的工作和个人项目长期并行，个人项目集中在长假爆发，然后用周刊和博客持续发声。十年后回头看，每一个假期都留下了一个「家人」。

代表作品详解

Mole 鼴 ↗

2025Shell CLI + 原生 Mac / WindowsCLI 开源（GPL-3.0）· Mac 版 $19

「清理几十 GB 垃圾和 AI 工具旧数据，卸载和更新软件，分析磁盘，维护系统，实时查看 Mac 运行状态。」Mac 版把五块功能做成太阳系里的五个星体，每颗都有自己的职责：

  • 地球 · 清理：系统数据单独成组；每一项都能选择、跳过或加入保护清单；扫描和清理都在本机完成，不上传任何文件。
  • 月亮 · 清 AI：Claude Code、Codex、Cursor 等 AI 工具的缓存和旧版本、很久没打开的 Codex 会话和 worktree、长期不用的 AI 命令行工具，逐条确认再删。
  • 火星 · 软件：从 Sparkle、App Store、Homebrew 等来源检查更新；卸载时一并检查残留，不确定的默认不选。
  • 水星 · 优化：需要管理员权限的任务集中授权一次，有风险的任务自动跳过并说明原因。
  • 木星 · 分析 / 太阳 · 状态：色块展示磁盘占用；实时查看 CPU、GPU、内存、温度、风扇，Apple 芯片还能看频率和功耗，以及配对的 iPhone、iPad 电量。

从 Mole for Mac 学到的事

  • 一直手工回邮件。答疑、退款、重置激活码加起来不到用户量的 1%，半小时就能写脚本自动化，但 TA 没写：「只有自己一封封处理过，才能感觉到用户到底要什么。」自动化要等到三件事都成立：问题反复出现、答案已经稳定、例外都摸清楚了。
  • 不先搭支撑系统。没有工单、客服平台、知识库。「AI 能把开发压缩到几天，但和人打交道不能省。」
  • 功能进路线图要过三道门：用户没点进这个功能就不能有常驻的定时器和采样开销；不能为一点小便利扩大特权或新增系统权限；有合理默认值时不加设置项。
  • 对清理工具来说，不删什么比删什么重要。保护名单就是这么来的。
  • 从第一天就全球化，英文内容发得比中文多；X 上的热度来得快去得也快，YouTube 上的内容衰减非常慢。
  • 没花钱做过推广，增长基本靠口碑，退款率低于 0.8%，买的人里有不少是长期使用 CLI 的老用户。

AI 产生的赛博垃圾已经够多了，与其拿 Token 再堆一个能跑就行的界面，我还是想做个舒服一点的东西出来，不浪费我的 Token，也不污染你的时间线。

— Tw93，解释 Mole 为什么要做五颗行星

五颗行星的贴图，TA 从 NASA 官网下了很多张，换了不下 10 次；转动方向、转速和完成后的飞行效果都照着真实的天体来做。这和 TA 小时候喜欢看行星运行，以及十年前「学会前端后第一个特别想学的就是 WebGL」有关。

长处与局限

维度长处局限 / 需要留意
产品克制、安静、默认值合理；把「不打扰」写成路线图规则坚持不加功能，部分高级用户的需求会被婉拒
工程Rust、Swift、Shell 全栈；发版频率极高，README 多语言项目越来越多，单人维护压力大（TA 也在周刊里承认过一段时间「沉迷 AI Coding」导致周刊变水）
写作周刊近六年不断更；长文体系化，复盘诚实长文以中文为主，海外读者主要通过产品认识 TA
商业开源 CLI + 付费 Mac 版，边界清楚；不靠营销靠口碑付费产品目前只有 Mole 一款，收入结构较单一

可以从 TA 身上学什么

  • 用节日给项目定节奏：长假是完整的整块时间，适合从零做一个新东西。
  • 给作品讲一个故事：「开源小家庭」让每个项目都有性格，比一份列表好记得多。
  • 开源与付费分清边界：CLI 永远免费开源，原生 Mac 版一次买断，用户能理解，也愿意买单。
  • 先一封封回信，再谈自动化：早期用户的每一封邮件，都是产品方向。
  • 写作是长期资产：周刊、长文和产品博客，一起构成了不靠投放的增长。
