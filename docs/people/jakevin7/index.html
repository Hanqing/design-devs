TA 到底在做什么？

卡比卡比的工作分成两个时代。数据库时代：在 Apache Doris、DataFusion、Arrow 社区长期贡献查询优化器和执行引擎，最终成为三个项目的 PMC 成员。Agent 时代：2026 年 3 月开始，TA 以极快的速度发布了一系列 CLI，目标都是同一个：让 AI Agent 能可靠地「查询」网站和本地数据。

这两个时代的方法论其实一样。数据库给 SQL 一个确定的执行计划；OpenCLI 给 Agent 一个确定的命令接口。数据库把每一次操作都写进日志；Maka 把 Agent 的每一次模型调用、工具调用和权限决定都写进只追加的事件日志。

本页依据 GitHub 个人主页自述、各项目 README、OpenCLI / Maka / Raft 官网与 X 资料整理，资料截至 2026 年 10 月。TA 在 Raft 的具体角色未见公开说明，因此只写「参与建设」。

OpenCLI ↗

2026.03JavaScript / Node.jsChrome 扩展 + 本地守护进程

「Convert any website into a CLI & run Browser Use on your logged-in Chrome.」它把网站和浏览器会话变成「对人和 Agent 都确定的接口」。一个工具，三种用法：

  • 内置适配器：B 站、知乎、小红书、Reddit、Hacker News、Twitter/X 等网站开箱即用。
  • 让 Agent 操作任意网站：在 Claude Code、Cursor 里安装 opencli-browser 技能，Agent 就能通过你已登录的 Chrome 导航、点击、填表、提取和截图，不需要任何适配器。
  • 编写新适配器：用 opencli-adapter-author 技能，从侦察、字段解码、写代码一路走到 opencli adapter test。
  • Agent 命令契约：命令默认输出 {"ok": true, "data": …}，失败时返回带 code、message、hint 的错误和非零退出码，日志走 stderr，便于 Agent 解析。
  • 桌面应用 OpenCLIApp：托盘界面负责安装、诊断、更新、保持浏览器登录态和网页转 Markdown。

Apache Maka（Incubating） ↗

2026.05TypeScriptApache 孵化器

「一个高性能的 Agent 工作区，完整记录它做过的每一件事。」Maka 的原则很有数据库味道：

  • 用测量代替宣称：在同一个模型、同一个官方验证器下和其他 Agent 框架对比，每次评测的逐任务结果都随报告发布。
  • 日志就是运行时：每一条模型消息、工具调用、权限决定和终止都是只追加的事件；界面、下一轮提示词和崩溃恢复都只是这份日志的投影。
  • 你的机器，你的模型：会话、设置和运行记录都留在本地；模型可以是云端 API、本地模型或兼容网关。
  • 一个运行时宿主：桌面端、TUI、CLI 和评测都是同一个执行中枢的薄客户端。

方法与观点

  • CLI 是 Agent 的最佳接口。命令行可组合、可脚本化、可审计，JSON 输出让 Agent 不必猜测页面结构。
  • 复用用户已有的状态。登录态、本地数据库，比重新对接每个平台的 API 快得多，也更贴近真实使用。
  • 可测量，才可信。Maka 的口号是「Measured, not claimed」，每次评测都公开逐任务记录。
  • 日志是唯一真相。这正是数据库系统的核心思想：一切状态都可以从日志重放出来。

The log is the runtime.

— Apache Maka README

长处与局限

维度长处局限 / 需要留意
系统能力三个 Apache 顶级项目的 PMC，底层功底扎实数据库方向的贡献分散在大型社区中，外界不易看到个人细节
产出速度一个模式跑通后迅速复制到十几个平台多个 CLI 基于逆向接口，平台改版后需要持续维护，也要留意各平台的使用条款
产品设计命令契约清晰，面向 Agent 优化以英文和开发者为主，普通用户上手需要一定门槛
方向同时推进 OpenCLI、Maka、Raft精力分配与长期维护有待观察

可以从 TA 身上学什么

  • 长期投入一个开源社区：从贡献者到 Committer 再到 PMC，需要的是持续数年的深度工作。
  • 给 Agent 设计接口契约：统一的 JSON 输出和错误格式，比更聪明的模型更能提高成功率。
  • 复用用户的已有状态：登录态和本地数据，是 Agent 落地最短的路。
  • 把老本行的思想迁移过来：执行计划、事件日志、可重放，这些数据库概念在 Agent 系统里同样成立。
